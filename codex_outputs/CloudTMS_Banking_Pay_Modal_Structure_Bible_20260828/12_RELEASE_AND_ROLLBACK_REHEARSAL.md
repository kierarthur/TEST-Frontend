## Fallback conditions

Fallback to legacy is allowed only:

- before any v2 mutation was dispatched in that modal; and
- after a read-only capability/dependency failure proves no mutation was submitted.

Fallback is forbidden:

- after mutation dispatch;
- during transport uncertainty;
- as a substitute for read-back;
- if both interface handlers would remain active;
- if it would reopen a second Workbench session.

## Immediate TEST rollback procedure

1. Stop new v2 sessions by setting capability false through the approved control.
2. Do not interrupt an uncertain in-flight mutation; let the v2 read-back path reach a terminal state.
3. Confirm new modal opens use the unchanged legacy interface.
4. Confirm no duplicate v2 listener/handler remains mounted.
5. Confirm Draft gate and selection from current server authority.
6. Leave additive database definitions dormant; do not run emergency destructive down SQL.
7. Preserve typed errors, correlation references, request timing and browser trace.
8. Record exact cause/affected commits/deployments.
9. Add executable regression proof before re-enable.

- Root cause fixed.
- Regression test fails before/fixes after.
- All affected Bible ledgers re-pass.

- No open D1/D2 deviation.
- Separate TEST activation approval where required.
